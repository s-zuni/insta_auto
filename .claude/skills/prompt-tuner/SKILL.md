# prompt-tuner

대상: `apps/agent/generators/{matrix_prompt,threads_gen,blog_gen}.py` 의 시스템 프롬프트와 `KOREAN_RULES`.

## 루브릭 (항목당 1~5점, 채널별 가중)
| 항목 | 기준 | 숏폼 | 쓰레드 | 블로그 |
|---|---|---|---|---|
| 자연스러움 | 번역투(`~에 대해`, `~를 통해`, `~것이 가능`), 피동 남발, 긴 문장 없음 | ×2 | ×2 | ×2 |
| 훅 | 첫 문장이 3초/첫 줄 안에 멈추게 하는가 | ×3 | ×3 | ×1 |
| 채널 톤 | 숏폼=또렷, 쓰레드=반말·친근·이모지 거의 없음, 블로그=정보형 존댓말 | ×1 | ×3 | ×1 |
| 구체성 | 업종·주제에 맞는 구체 정보/예시가 있는가 (뻔한 일반론 감점) | ×2 | ×1 | ×3 |
| 신뢰/안전 | 과장·허위·의학적 효능 단정·최상급 남발 없음 | ×2 | ×2 | ×2 |
| CTA | 부담 없고 명확한 행동 유도 | ×1 | ×1 | ×1 |
| 길이/형식 | 숏폼 장면당 ~40자, 쓰레드 글당 ≤500자, 블로그 1,200~1,800자·소제목 3~4개 | ×1 | ×2 | ×2 |

## 절차
1. **샘플 세트 생성**: `apps/agent/.venv` 로 `generate_all()` 을 **5개 조합**(업종 × 스타일 서로 다르게)으로 실행. `ANTHROPIC_API_KEY` 가 없으면 Mock 이라 튜닝 불가 → 중단하고 알린다.
2. **자가 채점**: 각 결과를 루브릭으로 채점하고 표로 출력. 감점 사유는 **원문 인용**으로 근거를 단다.
3. **번역투 스캔**: `~에 대해`, `~를 통해`, `~로 인해`, `~것이 가능`, `~하는 것이 중요`, 이중피동(`~되어지다`), `~하도록 하겠습니다` 등을 grep 으로 개수 집계.
4. **프롬프트 수정**: 가장 점수가 낮은 항목 1~2개만 겨냥해 수정 (한 번에 여러 개 바꾸지 않는다 → 원인 추적).
5. **재채점**: 같은 5개 조합으로 재생성·재채점해 **전/후 점수표**를 보고. 개선 없으면 되돌린다.

## 규칙
- 프롬프트 수정은 diff 로 보여주고 근거(어떤 점수가 왜 올랐는지)를 단다.
- 좋은/나쁜 예시는 프롬프트에 **few-shot** 으로 3개 이내만 넣는다 (토큰·편향 관리).
- 실제 고객 상호·개인정보를 예시에 넣지 않는다.
